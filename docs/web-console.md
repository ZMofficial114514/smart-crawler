# Web 控制台使用指南

SmartCrawler 的图形化入口。所有命令行能做的事,这里都有对应的可视化操作,
并且**所有可调参数都在「系统配置」页里**,改完直接写回 `.env`。

```
python -m smartcrawler web            # 默认 http://127.0.0.1:8322
python -m smartcrawler web --port 9000 --reload   # 换端口 / 开发热重载
```

启动后浏览器打开 `http://127.0.0.1:8322` 即可。接口文档在 `/api/docs`。

## 2. 抓取任务

### 两种规则来源

**自然语言(AI)** —— 填写目标页面 + 用中文描述想要什么:

> 抓取所有书籍的名称、价格和详情页链接

框架会先做结构分析(候选列表区 / 分页器 / JSON-LD 元数据),把结构报告和目标一起
发给大模型,要求返回严格 JSON 规则,校验通过后执行。未配置 API Key 时**自动降级**
到规则引擎(结构启发式),不会中断任务。

**手写规则** —— 直接给出 `ExtractionRule`:

```json
{
  "mode": "dom",
  "list_rule": {
    "item_selector": "article.product_pod",
    "fields": [
      { "name": "title", "selector": "h3 a", "attribute": "title", "transform": ["strip"] },
      { "name": "price", "selector": ".price_color", "transform": ["price"] },
      { "name": "link",  "selector": "h3 a", "attribute": "href", "transform": ["url"] }
    ]
  },
  "pagination": { "next_selector": "li.next a", "max_pages": 3 }
}
```

编辑器自带「插入模板 / 校验规则 / 格式化」三个按钮。校验走 `POST /api/rules/validate`,
只检查**结构合法性**;选择器是否命中真实元素需要实际抓取才能验证。

### 关键参数

| 参数 | 说明 |
|---|---|
| 输出格式 | `json` / `jsonl` / `csv` / `sqlite`;选「不落盘」则只在界面预览并可下载 |
| 输出路径 | 留空按时间自动命名到 `data/` |
| 最大翻页数 | 覆盖配置里的 `crawler.max_depth` |
| 额外等待 | 页面加载后再等 N 秒,给懒加载/异步接口留时间 |
| 增量抓取 | 基于内容哈希只输出新增内容(状态存 `data/state.json`) |
| 允许 AI 生成规则 | 关闭后使用规则引擎 |

### 进度时间线

提交后界面会建立 WebSocket(`/ws/tasks/{id}`),实时渲染 8 个步骤:
准备环境 → 启动浏览器 → 打开页面 → 分析结构 → 确定规则 → 提取数据 → 跟随分页 → 保存结果。
同时后端 loguru 的日志会经由 `/ws/logs` 推到底部的实时日志抽屉。

关于进度条的口径,有两点是刻意如此设计的:

- **进度表示"步骤完成比例",不是时间估算**。8 个步骤里只有少数几个能在过程中被精确
  标记(`准备环境` 是明确的,其余步骤的完成时刻要等整个任务返回才能确定),所以任务
  进行中进度条会**跳变**(例如 13% → 100%),而不是平滑爬升。这是为了不伪造精度。
- **任务一结束进度必定为 100%**。`TaskState.finish()` 会把进度灌满并把未显式标记的
  步骤补成 `done`,终态的 `status` 事件同时携带 `progress`。前端收到后会重新向后端
  拉一次任务详情来重绘时间线 —— 否则步骤圆点会停在灰色,与 100% 的进度条自相矛盾。

任务结束后:状态标签切到「已完成」、进度条 100%、8 个步骤全部变绿、「取消任务」隐藏、
「开始抓取」恢复可用、结果表格出现。

任务可以随时「取消」;取消后浏览器会话会被标记为脏,下次任务自动重建。

### 布局约定

抓取页是「左表单 + 右侧栏」两列。右侧栏(任务进度 + 快捷操作)整体使用
`position: sticky` 跟随滚动,并且:

- **粘滞作用在容器 `.stack--side` 上,而不是单张卡片**。对单张卡片做 sticky 时,它会
  脱离所在行的行高计算,一旦在粘滞期间"长高"就会与相邻卡片重叠;
- **结果卡不在这个 grid 里**,它是 `.grid--form` 的兄弟节点,因此天然占满整宽,
  既不挤压粘滞列也不参与其高度计算;
- 栅格**不用 `align-items: start`**,而用 `stretch` + 子项 `align-self: start`,
  这样行高按真实内容计算,sticky 才有正确的活动范围;
- 侧栏有 `max-height` 与自身滚动,内容比视口高时不会被裁掉;
- 窗口 ≤1280px 时降级为单列并取消粘滞。

`scripts/verify_ui_layout.py` 会用几何矩形相交**断言**这种不重叠(而不是靠肉眼看截图),
同时断言终态 UI 正确,可在改动样式后回归。

## 3. 结构分析

输入 URL,得到:

- **候选列表区**:按重复项数排序,每个都给出一键复制的 `item_selector` 与字段选择器;
- **分页器**:检测到的「下一页」选择器与按钮文字;
- **结构化元数据**:JSON-LD / Open Graph / Microdata;
- **简化 DOM 树**:手写选择器时用来定位层级;
- **DOM 统计**:节点数、链接数、表单数等;
- **访问受限诊断**(见下节)。

最有用的是「**用这份结构去抓取**」按钮:它会把最佳候选自动填进抓取页的手写规则编辑器,
并切换到该页 —— 省掉手工抄选择器。

### 3.1 访问受限诊断

抓不到数据时表面的结果都是"0 条",但底层原因差别极大,**处置方式完全不同**。
把它们混为一谈会让人往错误方向排查很久。因此结构分析与抓取都会做一次分类诊断。

| 类型 | 典型表现 | 处置方向 |
|---|---|---|
| `login_required` | 跳转 `/login`、有密码框 | 复用登录会话(`storage_state`) |
| `permission_denied` | **HTTP 401/403 但 URL 不变**,页面写"没有权限" | 账号确实无权限,或需先报名/加入 |
| `risk_control` | 风控页、Cloudflare 挑战、"检测到异常访问" | 降速、换 IP、开反爬增强插件 |
| `captcha` | 人机验证组件 | 降速或人工过一次验证 |
| `rate_limited` | 429 / "请求过于频繁" | 降速、降并发 |
| `spa_shell` | 页面几乎是空壳 | 内容异步渲染:增大等待或改用抓包 |
| `server_error` | 5xx | 站点故障,稍后重试 |
| `not_found` | 404 | 地址失效或写错 |
| `empty_page` | 页面正常但没有列表 | 选择器问题,或本来就没有数据 |

判定线索加权计分(阈值 0.5),得分明细会列在卡片上,让用户明白**为什么归到这一类**:

| 线索 | 权重 |
|---|---|
| "没有权限/无权限/未授权"(中文文案) | 0.75 |
| "权限不足 / 仅特定角色可见 / 需报名" | 0.55 ~ 0.6 |
| "访问频繁 / 操作频繁" | 0.7 |
| "风控 / 异常访问 / IP 封禁" | 0.7 ~ 0.8 |
| "人机验证 / 滑动验证" | 0.7 |
| 出现验证码组件 | 0.30 |
| 密码输入框 / 含密码框的表单 | 0.35 / 0.25 |
| 跳转目标带登录语义 | 0.35 |
| **HTTP 401**(中性线索) | permission 0.30 · login 0.15 |
| **HTTP 403** | 0.40 |
| 429 / 404 / 5xx | 0.6 ~ 0.7 |
| 可见内容极少且无可交互元素 | 0.50 |

**关键设计**:401/403 只说明"服务端拒绝",既可能是要登录也可能是没权限,所以把它们
当作**中性线索**,真正的分类交给页面文案与结构决定。同时 401/403/429 是硬信号 ——
即使关键词一个都没命中也会如实报出来。

### 3.2 卡片里有什么

判定成立时弹出醒目警示卡(按类型换色:权限类偏红、风控类偏紫),包含:

1. **请求 URL → 实际 URL**(仅在真的跳转时才画箭头)+ HTTP 状态码 + 类型徽标;
2. **判定依据**逐条列出;
3. **类型归因得分** —— 各候选类型的百分比,解释归因过程;
4. **页面关键文本元素** —— 带语义标签(标题/错误/表单/验证码/提示/按钮)、
   文本内容与 CSS 选择器。**这就是"提供页面显示的文本元素来找问题"的落点**;
5. **提取到的错误码 / 请求 ID**(若页面里有);
6. **按类型给出的处置建议**;
7. 可折叠的**页面完整可见文本**与**页面元数据 / 初始化变量**。

> 设计取舍:文本元素与得分默认展开(排查的核心信息),完整原文默认折叠(避免刷屏)。

同一张卡在**结构分析页**与**抓取页**共用同一份渲染函数,保证两处提示完全一致。

### 3.3 一个真实案例:洛谷训练页

`https://www.luogu.com.cn/training/1096881#scoreboard` 在无权限时:

- 返回 **HTTP 401,但 URL 完全不变** —— 不跳登录页;
- 由前端 JS 渲染出错误页:`Error - 洛谷` / `出错啦` / `没有权限请求此资源。`;
- 没有密码框,也没有登录表单。

诊断结论是 **`permission_denied`(置信度 100%)**,依据是"页面提示没有权限" +
"HTTP 401 表示请求未通过身份校验";卡片里如实展示 `div.l-card.card-content` 上的原文
`出错啦 没有权限请求此资源。`,建议指向"是否需要报名/加入""账号是否真有该资源权限"
—— 而**不会**建议去配置会话文件(那是登录问题的处置方式)。

> 只做**识别与提示**,不做自动登录。自动填充账号密码涉及凭据管理,风险与责任都远超本框架
> 的边界。推荐的合法做法是: 在有头模式下手动登录一次,把会话保存为 `data/session.json`,
> 再把「会话持久化文件」配置指向它,后续抓取自动复用 Cookie。

**防误报**:正常列表页置信度为 0.00。阈值 0.5 且各线索权重克制的目的就是
"宁可少报,也不要天天误报"。

### 3.4 顺带修掉的两个底层问题

1. **401 页面被整个丢掉**。早先 `BrowserManager.goto()` 把**任何** ≥400 都当作导航
   失败,重试 3 次后返回 `None` —— 于是页面明明已经渲染出来却被扔掉,用户只看到
   "页面导航失败",拿不到任何可排查信息。现在只有 5xx/429/408 这类**可重试**状态才
   重试,其它 4xx 视为导航成功并保留页面交给诊断层解释。
2. **SPA 时序抖动**。洛谷的错误文案由 JS 渲染,网络静默期结束时偶尔还没上屏,会被误判成
   "内容未渲染"。现在诊断带一次短轮询:采不到实质内容时最多重采 4 次(间隔 1.5 秒)。

回归脚本:`scripts/verify_access_control.py`(46 项 · 合成样本)与
`scripts/verify_luogu_case.py`(16 项 · 真实站点,已连续 3 次稳定通过)。

## 4. 登录与手动登录

### 4.1 为什么需要"手动登录"

有些内容必须登录才能看到,而且**登录前后页面结构可能完全不同** —— pixiv 首页就是
典型: 匿名访问时它是一个注册/登录引导页(只有几个字), 登录后才变成作品瀑布流。
如果不把这件事讲清楚, 结构分析会得出"这个网站没有列表"的错误结论, 用户则拿着完全
错误的方向去调选择器。

功能上**故意不做自动登录**:

- 自动填充账号密码涉及凭据的存储/加密/泄露面, 风险与责任远超框架边界;
- 验证码、短信、扫码本来就只有人能过;
- 采用"手动登录一次 + 复用会话"后, 框架**自始至终不接触用户密码**, 只保存服务端
  签发的 Cookie 与 localStorage。

### 4.2 登录状态识别

结构分析与抓取都会做一次登录状态判定, 结果放在报告的 `login_state` 里, 界面上以
提示条呈现,**双向**都有信号才下结论:

| 方向 | 信号 | 权重 |
|---|---|---|
| 未登录 | 文案出现"用 xx 账号登录 / 注册账号 / Sign in"(中英文) | 0.45 |
| 未登录 | 存在密码输入框 | 0.30 |
| 未登录 | 有登录/注册入口链接 | 0.25 |
| 未登录 | 表单提交到 login/accounts 等鉴权地址 | 0.25 |
| 未登录 | 完全没有任何已登录特征(补充证据) | +0.15 |
| 未登录 | ≥2 个鉴权表单且无已登录特征(SPA 文案未渲染时的兜底) | +0.35 |
| 已登录 | 有"退出登录" | 0.55 |
| 已登录 | **页头**有头像/用户菜单 | 0.30 |
| 已登录 | 页头有"我的收藏/关注/设置"这类仅登录后存在的入口 | 0.30 |
| 已登录 | 文案出现"我的收藏/个人中心" | 0.25 |

命中不足或两类接近时判为 `unknown` —— **宁可不说, 也不要误导**用户去登录一个根本不
需要登录的站点。判定依据会列在提示条里(可展开), 让用户理解"为什么说我没登录"。

### 4.3 手动登录流程

界面上点"登录一次"会打开一个**可见**的浏览器窗口:

1. 在弹出的窗口里正常登录(验证码/扫码都可以);
2. 框架每 2 秒探测一次登录状态, 界面上实时显示"还没登录 / 已登录";
3. 登录完成后点「我已登录, 保存会话」, 会话写入 `data/session.json`;
4. 之后的抓取自动带上这份会话。

会话文件等同于凭据, 因此: 接口**只返回掩码摘要**(Cookie 数量、域名、会话类 Cookie
的**名字**), 绝不回传值; `data/session.json` 与 `data/sessions/` 已在 `.gitignore` 中。

### 4.4 实现要点

**浏览器跑在独立进程里**。Playwright 的浏览器对象绑定在创建它的 asyncio 事件循环上,
不可能"这个 HTTP 请求打开浏览器、下一个请求继续用"。所以 `scripts/login_helper.py`
作为独立进程负责打开窗口并等待用户操作, 主服务只做两件事: 读 `.runtmp/login_flow/`
下的状态文件展示进度、写信号文件下达"保存/取消"。

> 一点设计取舍: 长连接(HTTP 流)本可以省掉轮询, 但主服务重启会让界面卡在"进行中";
> 用文件 + 轮询更笨却更稳, 出问题时也能直接看 `helper.log`。

### 4.4 手动过人机验证

有些站点每次登录都会拉起人机验证(例如 pixiv), 还有站点在抓取中途突然弹挑战
(reCAPTCHA / Cloudflare Turnstile / 极验滑块)。这类验证**只有人能过**, 框架既不该也
无法代劳 —— 绕过它既不可靠也不合规。所以做法与手动登录一致: 识别 → 提示 → 打开可见
窗口让用户过 → 存下通行凭据 → 继续。

分析或抓取时若检测到挑战, 页面顶部会出现提示条与「**手动过验证**」按钮; 点开后在弹出
窗口里完成验证, 回来点『验证已完成, 保存会话』即可, 通行凭据(`cf_clearance` 等)会自动
进入会话文件, 之后的抓取不再遇到同一个挑战。

**识别上的关键难点是"别误报"**。很多站点(含 pixiv)每次访问都会挂上 reCAPTCHA 的
anchor iframe, 但只在部分情况才真的弹出挑战。实测数据:

| 状态 | 页面表现 |
|---|---|
| 已加载但未挑战 | anchor iframe 存在, 尺寸 256×60, 但 `visibility: hidden` |
| 正在挑战 | 出现**可见**的 bframe / 挑战容器(尺寸 ≥ 100×60) |

因此判据是"**可见的**挑战元素", 而不是"页面上提到了 captcha"。若按后者判断, 就会变成
每次访问都提示"需要人机验证" —— 比不提示更糟。另外纯文案提示(如页脚的
"This site is protected by reCAPTCHA")单独不作为判据, 必须有元素级证据。

覆盖的挑战类型:Google reCAPTCHA / hCaptcha / Cloudflare Turnstile / 极验(Geetest) /
Arkose Labs / 腾讯验证码。识别结果同时写入任务结果与分析报告的 `challenge` 字段。

> 实现上复用了手动登录那一套(同一个辅助进程, `--mode challenge`), 区别只在判据:
> 登录模式看"是否已登录", 挑战模式看"挑战是否消失"。若用户提前点了确认但挑战其实还在,
> 状态里会如实写明"验证可能还没过完" —— 不假装成功。

## 5. 网络抓包

用于找「真正的数据接口」。很多现代的列表页其实是 XHR 拉 JSON,直接解析接口比解析
HTML 稳定得多。

参数:捕获等待秒数、是否先模拟滚动、URL 正则、MIME、状态码、资源类型、只看 JSON 响应。

抓到记录后点击任意一条可查看请求详情(响应头/请求体/响应 JSON)。**若该响应是 JSON,
弹层里会出现「用这条响应的 JSON 生成提取规则」按钮** —— 它会推断条目数组的 JSONPath
(识别 `data.list` / `items` / `results` 等常见命名)和字段路径,生成 `mode: "json"` 规则
并填入抓取页。

## 6. 插件

左侧「插件」页管理全部扩展能力。两条路径:

- **声明式配置**(`声明式扩展` 插件): 不写代码即可配置附加请求头、正则批量下载、
  补充固定字段、额外导出 CSV/JSONL;
- **Python 单文件插件**: 往项目根 `plugins/` 丢一个 `.py` 即被自动发现。

内置 **图片下载器默认启用**,所以装好就能看到效果 —— 抓取时会把图片下载到
`data/plugin_output/images/`,并在抓取结果区渲染出「插件下载产物」卡片(文件名、
体积、MIME、成功比例、来源插件)。

插件的加载、配置、钩子、编写方式与完整接口清单见
**[plugins.md](plugins.md)**。

页面要素: 统计卡(总数/已启用/用户插件/加载失败)、常驻安全警示、搜索框、
按分类分组的插件卡片、自动生成的配置表单、源码查看与新建插件向导。

任务结果里会带 `plugins_used`、`downloads`、`plugin_errors` 三项,界面据此渲染
产物卡片与错误提示。**插件故障一律隔离**:单个插件崩溃只记录错误,不影响抓取结果。

## 7. 结果与历史

- **任务历史**:本次会话内所有任务(抓取/分析/抓包),含状态、耗时、条数;
- **产出文件**:`data/` 与 `data/web_tasks/` 下的文件,支持预览(文本/JSON)、下载、删除;
- 点击任务可回溯完整结果:超过 300 条的预览上限时,可点「在抓取页继续查看」。

任务完整结果会落盘到 `data/web_tasks/<kind>_<task_id>.json`(含全部条目),
通过 `GET /api/tasks/{id}/download` 下载。

## 8. 系统配置

**54 个配置项**按 8 个分组呈现:浏览器引擎 / 网络监听 / AI 辅助 / 反爬与合规 /
存储输出 / 抓取行为 / 调试服务 / 通用与日志。

设计上由后端 Schema 驱动(见 `web/config_store.build_config_schema`,通过 Pydantic
模型内省生成),所以往 `config.py` 里加一个字段,界面会自动多出一个带校验的控件。

行为约定:

- 只有**真正改动过**的字段才会写入 `.env`,不会覆盖你手写的注释与顺序;
- API Key 以掩码回显(`sk-6********d51a`),留空表示不修改;
- 数值字段有范围校验,JSON 字段有语法校验,错误就地提示且不阻塞其他字段;
- 标记「需重启会话」的字段(引擎/无头/视口/代理等)保存后,下次任务会用新参数重建浏览器;
- 若某个键同时存在于**真实环境变量**中,会提示"被环境变量锁定"——因为环境变量优先级
  高于 `.env`,写 `.env` 不会生效。

### 自检与维护

| 按钮 | 作用 |
|---|---|
| 测试 AI 连通性 | 发一条最小对话,返回耗时与实际回复,验证 Base URL / 模型名 / Key |
| 探测代理池 | 逐个代理访问 ipify,返回可用比例、延迟与出口 IP |
| 清空 AI 缓存 | 删除 `data/ai_cache.json`,强制重新推理 |
| 重置增量状态 | 清空已见内容哈希,下次抓取视为全量 |

## 11. 常见问题

**怎么一键启动?**
Windows 上双击项目根的 `start.bat` 即可 —— 它会自动找 Python、按需建 `.venv`、补齐依赖、
检查并下载浏览器内核、检查端口占用,然后启动服务并打开浏览器。参数见
`start.bat --help`(`--port` / `--no-browser` / `--check` / `--reload`)。

两个实现细节值得说明,因为都踩过坑:

- **`.bat` 里刻意只有 ASCII 字符**。`cmd.exe` 按控制台 OEM 代码页(简体中文为 GBK)
  **逐字节**解析批处理文件,文件里若有 UTF-8 多字节中文,解析器会被拆散并报出一堆
  `'------' is not recognized as an internal or external command`。所以中文界面全部放在
  `scripts/launcher.py`(Python 按 UTF-8 读取,天然安全)。
- **控制台代码页与 Python 输出必须一致**。`start.bat` 会 `chcp 65001`,Python 侧则调用
  `force_utf8_output()` 把 stdout/stderr 切成 UTF-8。两者缺一会导致中文乱码。

**命令行启动时启动横幅是乱码?**
已修复。原先 `cli.main()` 在 `setup_logging()` **之前**打印横幅,而只有后者会把 stdout
切成 UTF-8,于是横幅以 GBK 输出。现在 `smartcrawler.cli` 一导入就调用
`force_utf8_output()`。若你自行调用核心模块打印中文,记得先调它。

**界面上的实时日志是空的?**
确认服务是通过 `python -m smartcrawler web` 启动的。若自行用 uvicorn 启动,日志初始化
由 ASGI lifespan 负责,不应在导入期调用 `logger.remove()`(会移除日志总线 sink)。

**AI 显示"未配置 Key",但 `.env` 里明明有?**
检查是否有同名**真实环境变量**遮蔽了 `.env`(环境变量优先级更高)。系统配置页会把
这类键标记为"被环境变量锁定"。

**Base URL 填了裸域名会不会 404?**
不会。框架会自动补全缺失的版本段(`https://api.deepseek.com` → `.../v1`),
已带 `/v1` 的原样使用。

**浏览器内核需要单独下载吗?**
需要,但不必用官方安装器:

```bash
python scripts/bootstrap_browsers.py          # 带进度、断点续传、自动重试
```

它会把内核装到项目内的 `.browsers/`,并在启动时自动指向那里(无需配置环境变量)。
这样做同时也避开了系统临时目录/用户缓存目录不可写的受限环境问题。

**改动配置会破坏我的 `.env` 注释吗?**
不会。写入是行级合并:保留注释、空行与顺序,只替换对应的键值,新键追加到末尾。
